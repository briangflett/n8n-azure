## Backup and Recovery

### Backup Configuration

**PostgreSQL Automated Backups**:
- **Frequency**: Daily
- **Retention**: 15 days
- **Type**: Full backup
- **Storage**: Geo-redundant disabled (cost optimization)

**Key Vault Backups**:
- **Soft Delete**: Enabled (90-day retention)
- **Purge Protection**: Not enabled
- **Recovery**: Secrets recoverable for 90 days after deletion

**Container Registry**:
- **Image Tags**: Preserved
- **Soft Delete**: 7-day retention

### Manual Database Backup

Create on-demand backup before major changes:

```bash
az postgres flexible-server backup create \
  --resource-group mas-n8n-rg \
  --name mas-n8n-postgress-db \
  --backup-name "manual-backup-$(date +%Y%m%d-%H%M)"
```

### List Available Backups

```bash
az postgres flexible-server backup list \
  --resource-group mas-n8n-rg \
  --name mas-n8n-postgress-db \
  --output table
```

## Disaster Recovery

### Recovery Time Objectives (RTO/RPO)

- **RTO (Recovery Time Objective)**: 30 minutes
  - Time to redeploy from scripts if complete failure

- **RPO (Recovery Point Objective)**: 24 hours
  - Daily database backups, up to 24 hours of data loss possible

### Recovery Scenarios

#### Scenario 1: Container App Failure

**Recovery Steps**:
```bash
# Quick restart
az containerapp restart --name mas-n8n-app --resource-group mas-n8n-rg

# If restart fails, redeploy
cd /home/brian/workspace/deployments/azure/n8n-azure
./3_deploy_container_app.sh

# Verify recovery
az containerapp show --name mas-n8n-app --resource-group mas-n8n-rg \
  --query "properties.runningStatus"
```

**Estimated Recovery Time**: 2-5 minutes

#### Scenario 2: Database Corruption

**Recovery Steps**:
```bash
# 1. List available backups
az postgres flexible-server backup list \
  --resource-group mas-n8n-rg \
  --name mas-n8n-postgress-db

# 2. Stop application to prevent new writes
az containerapp update \
  --name mas-n8n-app \
  --resource-group mas-n8n-rg \
  --min-replicas 0 \
  --max-replicas 0

# 3. Restore to specific point in time
az postgres flexible-server restore \
  --resource-group mas-n8n-rg \
  --name mas-n8n-postgress-db-restored \
  --source-server mas-n8n-postgress-db \
  --restore-time "2026-01-27T12:00:00Z"

# 4. Update container app to use restored database
# (Update connection string in environment variables)

# 5. Restart application
az containerapp update \
  --name mas-n8n-app \
  --resource-group mas-n8n-rg \
  --min-replicas 1 \
  --max-replicas 3
```

**Estimated Recovery Time**: 15-30 minutes

#### Scenario 3: Complete Resource Group Deletion

**Recovery Steps**:
```bash
cd /home/brian/workspace/deployments/azure/n8n-azure

# Run all deployment scripts in order
./1_create_workload_profile.sh
./2_build_image.sh
./3_deploy_container_app.sh

# Reconfigure custom domain DNS (if needed)
# Wait for SSL certificate provisioning

# Note: Database will be empty - restore from backup if available
# Note: Secrets will be regenerated - update clients if needed
```

**Estimated Recovery Time**: 45-60 minutes

**Data Loss**: Depends on backup age (up to 24 hours)

#### Scenario 4: Key Vault Secret Loss

**Recovery Steps**:
```bash
# Secrets are auto-generated by deployment script
# Re-run deployment to regenerate
cd /home/brian/workspace/deployments/azure/n8n-azure
./3_deploy_container_app.sh

# Note: This changes passwords
# Update PostgreSQL password to match Key Vault
DB_PASSWORD=$(az keyvault secret show \
  --vault-name mas-n8n-kv \
  --name N8N-DB-Password \
  --query "value" --output tsv)

az postgres flexible-server update \
  --resource-group mas-n8n-rg \
  --name mas-n8n-postgress-db \
  --admin-password "$DB_PASSWORD"

# Restart container
az containerapp restart --name mas-n8n-app --resource-group mas-n8n-rg
```

**Estimated Recovery Time**: 10-15 minutes

## Community Nodes

Community nodes are installed on container startup via `docker-entrypoint.sh`. This is necessary because Azure Container Apps has **ephemeral filesystem storage** - any npm packages installed at runtime (e.g., via the n8n UI) are lost when the container restarts.

### How It Works

1. `docker-entrypoint.sh` runs before n8n starts
2. It checks if community node packages exist in `/data/.n8n/nodes/`
3. If missing, it runs `npm install` to install them
4. Then starts n8n via `exec n8n start`

n8n discovers community nodes by scanning `/data/.n8n/nodes/node_modules/` for packages matching `n8n-nodes-*` or `@*/n8n-nodes-*`.

### Current Community Nodes

| Package | Version | Node |
|---------|---------|------|
| `@ixiam/n8n-nodes-civicrm` | 1.1.41 | CiviCRM |
| `@tavily/n8n-nodes-tavily` | 0.5.1 | Tavily |
| `n8n-nodes-mcp` | 0.1.37 | MCP Client |

### Adding or Updating Community Nodes

1. Edit `docker-entrypoint.sh` - update the npm install line with new packages/versions
2. Update the existence check (`if` condition) to include the new package path
3. Rebuild and deploy:
   ```bash
   cd /home/brian/workspace/deployments/azure/n8n-azure
   az acr build --registry masbgfn8nacr --image mas-n8n-image:$(date +%Y%m%d) \
     --file Dockerfile.azurelinux .
   az containerapp update --name mas-n8n-app --resource-group mas-n8n-rg \
     --image masbgfn8nacr.azurecr.io/mas-n8n-image:$(date +%Y%m%d)
   ```

### Why Not Bake Into the Dockerfile?

Two approaches were tried:
- **Dockerfile `npm install` into n8n's global directory**: Packages get hoisted by npm and n8n can't find them
- **Dockerfile `npm install` into `/data/.n8n/nodes/`**: The `VOLUME ["/data"]` directive causes anything written during build to be lost when the volume is mounted at runtime

The entrypoint script approach works because it runs **after** the volume is mounted.

### Troubleshooting Community Nodes

If nodes show warning triangles in the UI or logs show "Unrecognized node type":

```bash
# Check if entrypoint ran successfully
az containerapp logs show --name mas-n8n-app --resource-group mas-n8n-rg --tail 50

# Look for "Installing community nodes..." and "Community nodes installed successfully."
# If not present, the entrypoint may have failed
```

## Building and Deploying Images

### Build Process

WSL doesn't have Docker Desktop, so use Azure Container Registry cloud builds:

```bash
cd /home/brian/workspace/deployments/azure/n8n-azure

# Build with a date-based tag
az acr build --registry masbgfn8nacr \
  --image mas-n8n-image:$(date +%Y%m%d) \
  --file Dockerfile.azurelinux .
```

### Deploy Process

```bash
# Deploy the new image (use the same tag from the build step)
az containerapp update --name mas-n8n-app --resource-group mas-n8n-rg \
  --image masbgfn8nacr.azurecr.io/mas-n8n-image:TAG

# Verify new revision is running
az containerapp revision list --name mas-n8n-app --resource-group mas-n8n-rg \
  --query "[?properties.active].{name:name, created:properties.createdTime, image:properties.template.containers[0].image}" -o table
```

### Image Tagging

**Always use a unique tag** (e.g., date-based like `20260223`). Using `:latest` alone will **not trigger a new revision** because Azure Container Apps only creates a new revision when the image reference string changes. If the tag is always `:latest`, Azure sees no change and keeps the old revision running.

## Updating n8n Version

### Standard Update Process

**When to Update**:
- Security patches
- New features needed
- Bug fixes
- Monthly maintenance

**Update Steps**:

1. **Check current version**:
   ```bash
   # Check running container version
   az containerapp logs show --name mas-n8n-app --resource-group mas-n8n-rg \
     | grep "n8n ready" | head -1
   ```

2. **Review release notes**:
   - Visit https://docs.n8n.io/release-notes/
   - Check for breaking changes
   - Review database migration requirements

3. **Create database backup**:
   ```bash
   az postgres flexible-server backup create \
     --resource-group mas-n8n-rg \
     --name mas-n8n-postgress-db \
     --backup-name "pre-upgrade-$(date +%Y%m%d)"
   ```

4. **Rebuild image with latest n8n**:
   ```bash
   cd /home/brian/workspace/deployments/azure/n8n-azure
   ./2_build_image.sh
   ```

5. **Deploy updated image**:
   ```bash
   ./3_deploy_container_app.sh
   ```

6. **Verify deployment**:
   ```bash
   # Check status
   az containerapp show --name mas-n8n-app --resource-group mas-n8n-rg \
     --query "properties.runningStatus"

   # Check logs for errors
   az containerapp logs show --name mas-n8n-app --resource-group mas-n8n-rg --tail 100

   # Test login
   curl -I https://n8n.masadvise.org

   # Test workflow execution (manual test in n8n UI)
   ```

7. **Document version**:
   ```bash
   # Record in CHANGELOG.md
   echo "## $(date +%Y-%m-%d) - n8n Update" >> CHANGELOG.md
   echo "- Updated n8n to version X.Y.Z" >> CHANGELOG.md
   git add CHANGELOG.md
   git commit -m "Update n8n to version X.Y.Z"
   ```

### Rollback Procedure

If update causes issues:

```bash
# 1. Find previous revision
az containerapp revision list \
  --name mas-n8n-app \
  --resource-group mas-n8n-rg \
  --output table

# 2. Activate previous revision
az containerapp revision activate \
  --name mas-n8n-app \
  --resource-group mas-n8n-rg \
  --revision <previous-revision-name>

# 3. Deactivate problematic revision
az containerapp revision deactivate \
  --name mas-n8n-app \
  --resource-group mas-n8n-rg \
  --revision <problematic-revision-name>

# 4. If database migration occurred, restore from backup
az postgres flexible-server restore \
  --resource-group mas-n8n-rg \
  --name mas-n8n-postgress-db-rollback \
  --source-server mas-n8n-postgress-db \
  --restore-time "<time-before-upgrade>"
```

## Security Maintenance

### Monthly Security Checklist

1. **Review RBAC permissions**:
   ```bash
   # List access to Key Vault
   az role assignment list \
     --scope "/subscriptions/$AZURE_SUBSCRIPTION_ID/resourceGroups/mas-n8n-rg/providers/Microsoft.KeyVault/vaults/mas-n8n-kv" \
     --output table
   ```

2. **Review network access**:
   ```bash
   # Check PostgreSQL firewall rules
   az postgres flexible-server firewall-rule list \
     --resource-group mas-n8n-rg \
     --name mas-n8n-postgress-db \
     --output table
   ```

3. **Review Container App access**:
   ```bash
   # Check authentication settings
   az containerapp show \
     --name mas-n8n-app \
     --resource-group mas-n8n-rg \
     --query "properties.configuration.ingress"
   ```

4. **Rotate secrets** (every 90 days):
   ```bash
   # Generate new admin password
   NEW_PASSWORD=$(openssl rand -base64 32)

   # Update Key Vault
   az keyvault secret set \
     --vault-name mas-n8n-kv \
     --name N8N-Admin-Password \
     --value "$NEW_PASSWORD"

   # Restart container to pick up new secret
   az containerapp restart --name mas-n8n-app --resource-group mas-n8n-rg
   ```

5. **Review logs for suspicious activity**:
   ```bash
   az containerapp logs show --name mas-n8n-app --resource-group mas-n8n-rg \
     | grep -i "failed\|unauthorized\|forbidden"
   ```

## Database Maintenance

### Optimize Database Performance

**Analyze table bloat**:
```sql
-- Connect to database
psql -h mas-n8n-postgress-db.postgres.database.azure.com \
     -U brian \
     -d n8n

-- Check table sizes
SELECT
  schemaname,
  tablename,
  pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename)) AS size
FROM pg_tables
WHERE schemaname = 'public'
ORDER BY pg_total_relation_size(schemaname||'.'||tablename) DESC;

-- Vacuum analyze
VACUUM ANALYZE;
```

### Upgrade Database Tier

If performance is consistently poor:

```bash
# Upgrade to General Purpose tier
az postgres flexible-server update \
  --resource-group mas-n8n-rg \
  --name mas-n8n-postgress-db \
  --sku-name Standard_D2s_v3 \
  --tier GeneralPurpose

# Increase storage
az postgres flexible-server update \
  --resource-group mas-n8n-rg \
  --name mas-n8n-postgress-db \
  --storage-size 64
```
